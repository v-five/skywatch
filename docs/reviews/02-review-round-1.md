### The ten that matter most

1. **R1-1** `claude-code/LICENSE` is still one line, and there is no `NOTICE` anywhere. Review 01 marks B1 resolved and the architecture lists both files. The MIT grant, Stephen Casella's copyright and any Apache-2.0 text for the code ported from Anthropic are missing from the folder that ships.
2. **R1-2** The force field fails open. `tool.check` writes state, logs and refreshes the status *before* it returns its verdict, and `tool.call` writes and measures before `next`. If any of those throws, the engine skips the hook: a `block` directive lets the call run, and a `hold` never asks.
3. **R1-3** The classifier cannot see past a single `&`, `|&`, `time -p` or `env -i`. For example, `sleep 1 & rm -rf build` and `true & git push --force` classify as nothing, so a hold or block directive is bypassed. Verified on the new code.
4. **R1-4** A rejected `next(e)` in `tool.call` leaves the held call in `runtime.held` for good. The pane then shows "Held · waiting" and Force field "waiting 1" until a reload. `callerOf` already uses `.finally`; `held` does not.
5. **R1-6** The normalizers only fill keys that are missing. A wrong-typed stored value passes under a cast: `{ steps: '3' }` reads as a Bridge, and the next `withStep` writes `steps: '31'`. A stored check without `id` or `detail` reads as a `Check`.
6. **R1-7** `Runtime.callerOf` exists because "tool.check carries no shuttle id". The engine's `ToolCheckInput` does carry `agentId`, so the map, its bookkeeping and the comment can go.
7. **R1-28** The main hook flows are untested: compaction counting, `turn.step` speed and tokens, the edit and error bookkeeping, hand-back advice, server-tool transmissions, probes, `session.end` clear, the beacon status entry and the terminal hint tail, `migrateState`, and the slash-command bridge state.
8. **R1-5** **Regression.** `measure`'s catch drops `.message` from a non-`Error` rejection, so the held note reads `Could not measure: [object Object]`.
9. **R1-37** The resolution table in review 01 is wrong for B1, C10 and C12. Reopen them.
10. **R1-34** Sections 6, 7 and 11 and the tree in section 3 of `docs/architecture.md` still describe signatures and files that are not in the code. These are the `Runtime.surface` type, `Connector`, `ModuleFrame`, `Bar`, `WorldOptions` and the `NOTICE` files.

### R1-1 · bug · `claude-code/LICENSE:1`, `docs/architecture.md:42,59`, `docs/reviews/01-conformance.md:476`

**What:** The shipped license is still the single line `Copyright (c) 2026 v-five`, and `git diff HEAD` shows the full MIT text deleted. No `NOTICE` file exists at the root or in `claude-code/`.

Review 01 says B1 was "Replaced by the license step: both `LICENSE` files and a `NOTICE` keep every copyright". The architecture tree also lists `LICENSE, NOTICE` in both places.

Ten files in `src/forcefield/` carry `SPDX-License-Identifier: Apache-2.0` (Anthropic PBC), but no copy of the Apache License 2.0 is in the repo.

**Cost:** `marketplace.json` installs from `./claude-code`, so every install gets a copy that has neither the MIT grant nor Stephen Casella's notice. MIT §2 requires that notice. Apache-2.0 §4(a) requires giving recipients a copy of the license.

**Fix:**
- Restore `claude-code/LICENSE` from `HEAD`, or copy the root `LICENSE` over it.
- Add `claude-code/NOTICE` and a root `NOTICE` that name the Apache-2.0 portions (the `src/forcefield` files with the header), with the Apache-2.0 text or a `LICENSE-APACHE` file.
- Reopen B1 in review 01.

### R1-2 · bug (pre-existing, deferred by architecture §6) · `src/events/tools.ts:116-127`, `:30-56`, `:129-136`

**What:** The engine skips a hook that throws, and "its last `next` result stands" (engine types, `EngineEventOf`). In `tool.check`:
1. `gateVerdict` computes the block or ask.
2. `recordVerdict` then runs `patchShields`, `logEntry`, `patchShields` again and `refreshStatus` (`$.ui.status`, plus four state reads for the beacon).
3. Only then does the hook return the verdict.

In `tool.call`, `noteCall`, `holdFor` (state reads) and `whoIs` run before `next`.

**Cost:** A throw in that bookkeeping turns the force field off for that call. Examples are a state write failing, `$.ui.status` being unavailable on a headless or SDK host, or a hook overrunning its budget. In `tool.check` the engine's own `found` verdict stands, so a `block @git-history` lets `git push --force` run. In `tool.call` the call runs unheld. Nothing tells the person, apart from a dim `skywatch:` line.

**Fix:**
- In `tool.check`, decide first and keep the decision independent of bookkeeping. Wrap `recordVerdict` in `try/catch`, or move it after a `return`-safe point, and return `verdict` regardless.
- Register `.catch` on `tool.check`, returning `{ decision: 'deny' }` when `runtime.held.get(id)?.mode === 'block'` and the engine's verdict otherwise.
- On `tool.call`, use `.catch(($, e, next) => next.called ? next(e) : …)` as the engine docs suggest.
- This changes the `gating hook without .catch` baseline lines, so it is a separate `fix:` commit, as §6 already plans.

### R1-3 · bug (pre-existing) · `src/forcefield/shell.ts:8,11`, `src/forcefield/classify.ts:60`

**What:** `SEPARATORS` is `&&|\|\||;|\||\n`, so a single `&` (background) and `|&` do not split segments. The prefix skipper drops `time` and `env` but not their options. Run in a copy of the new code:

| Command | `classifyAll` labels |
| --- | --- |
| `sleep 1 & rm -rf build` | `[]` |
| `true & git push --force` | `[]` |
| `echo ok \|& rm -rf x` | `[]` |
| `time -p rm -rf z` | `[]` |
| `env -i rm -rf q` | `[]` |
| `rm -rf build &` | `['rm -rf']`, with `&` read as a target path |

**Cost:** Any hold or block directive is bypassed by putting a `&`, `|&`, `time -p` or `env -i` in front of the command. That covers a user's `block @git-history`, the default `hold @secrets` and the other default holds. Claude writes `cmd &` lines routinely.

**Fix:**
- Split at a lone `&` that is not part of `&&`, `>&`, `&>` or `2>&1`, and at `|&`.
- In `commandWords`, drop the options of `time` (`-p`, `-v`) and of `env` (`-i`, `-u NAME`, `-S`, `--`).
- Strip a trailing `&` before tokenizing.
- Add these lines to `tests/support/corpus/shell.ts`. The golden output changes, so this is a `fix:` commit with its own test, not part of the refactor.

### R1-4 · bug (pre-existing, low) · `src/events/tools.ts:134-138`

**What:**
- `runtime.held.set(id, …)` happens before `next(e)`, and the entry is removed only by `settleHeld` after `next` resolves.
- `callerOf` is cleaned with `.finally`, so the code already allows for `next` rejecting (an abort, for example).
- `held` has no such cleanup.

**Cost:** If `next` rejects after `tool.check` set `since`, the entry stays. `heldNow` keeps returning it, and the pane shows a Held block with a running clock and Force field "waiting 1" until the mod reloads.

**Fix:** Run the settle in a `finally`: `try { ran = await next(e) } finally { runtime.callerOf.delete(id); if (ran === undefined) runtime.held.delete(id) }`, or delete in `finally` and keep a local copy for `settleHeld`.

## Regressions

### R1-5 · regression · `src/forcefield/measure/index.ts:42-45`

**What:** The old code wrote `String(error?.message ?? error)`. The new code writes `error instanceof Error ? error.message : String(error)`, so a rejection with a plain object such as `{ message: 'timeout' }` (the shape engine and host errors often take) now prints `[object Object]`.

**Cost:** The held call's note reads `Could not measure: [object Object]` where it used to give the reason.

**Fix:** `const reason = isRecord(error) && typeof error.message === 'string' ? error.message : String(error)`.

## Design

### R1-6 · design (type safety) · `src/core/guards.ts:6-8`, `src/domain/normalize.ts:65-76`, `src/domain/bridge.ts:41`

**What:**
- `mergeDefaults` spreads the stored object over the defaults and casts the result to `T`. It fills only keys that are absent; a present key of the wrong type passes through.
- `normalizeCheck(check as Check)` checks only `verdict` and `deck`.

In a scratch run:
- `normalizeBridge({ model: null, steps: '3' })` returns `model: null, steps: '3'` typed as `Bridge`.
- `normalizeShields({ recent: [{ verdict: 'ask' }] })` returns a check with no `id`, `tool`, `detail`, `inSubagent` or `at`.

**Cost:**
- `withStep` then writes `steps: '3' + 1 === '31'`, and the Hull row shows "31 calls".
- A check without `id` never settles, and one without `detail` draws an empty row.

The contract calls these fields required, and §5 says normalization makes every read safe, but only presence is guaranteed. The normalize tests (R1-31) check key presence only, so they cannot catch this.

**Fix:** Add a typed per-field merge, for example `mergeFields(defaults, stored, { steps: isNumber, model: isString, … })`, or a small `numberOr`/`stringOr` pass in each normalizer. Filter `recent` to records with a string `id`. Assert types in `normalize.test.ts`.

### R1-7 · design · `src/events/runtime.ts:16-17`, `src/events/tools.ts:42,132,136`

**What:** `callerOf` maps `tool_use_id` to the agent, because "tool.check carries no shuttle id". The engine's `ToolCheckInput` has `agentId?: string` ("on a real call inside a subagent's or a teammate's loop: the one its `tool.call` carried").

**Cost:** One extra map, a write and a `.finally` per call, plus a comment that is false.

**Fix:** `inSubagent: Boolean(e.agentId)` in `recordVerdict`. Delete `callerOf`, its two writes and the comment. Update §6.

### R1-8 · design · `src/forcefield/verdict.ts:3`, `src/domain/shields.ts:34-38`, `src/events/tools.ts:35,49`

**What:**
- `Decided` re-declares the engine's `ToolCheckDecision`.
- `checkVerdict(decision: string, …)` turns any unknown string into `'ask'`.
- `recordVerdict`'s `gate: { decision: string; isBlocked: boolean; held?: Held }` lets `held` be absent when `isBlocked` is true, and then logs `blocked by directive "undefined"` (`gate.held?.directive`).

**Cost:** Types that cannot catch a misuse, and one optional chain that hides a broken invariant.

**Fix:** Type `decision` as `ToolCheckDecision` from `'claude-code'`. Have `gateVerdict` return `{ verdict, blockedBy: string | null }`. Pass `blockedBy` to `recordVerdict`, and make `checkVerdict` a `Record<ToolCheckDecision, Verdict>` lookup plus the blocked case.

### R1-9 · design (dead data) · `src/forcefield/risk.ts:29-40`, `src/forcefield/hold.ts:72-73`

**What:** `Held.id` and `Held.command` are written by `holdFor` and never read. The map key already is the id, and no component draws `command`. The old code carried the same dead fields.

**Cost:** Two fields every reader must reason about; `command` also holds the unredacted command line in memory for no use.

**Fix:** Drop both from `Held` and `HoldDraft`, along with the `described` variable where only `headline` needs it.

### R1-10 · design · `src/ui/context.ts:8`, `src/events/runtime.ts:4,31-36`

**What:** `ActiveHold` ("a held call whose prompt is up") is declared in the UI layer, and the events layer imports it to type `heldNow`.

**Cost:** The runtime's own state type depends on the UI package, and the guard `isActive` lives far from `Held`.

**Fix:** Move `ActiveHold` and the `since !== null` guard to `src/forcefield/risk.ts`, next to `Held`, and import it from there in both places.

### R1-11 · design · `src/events/render.tsx:38-47`

**What:** The event layer builds `UiContext`. It applies the UI's minimum width (`Math.max(PANE_MIN_WIDTH, …)`) and the hazard-colour fallback (`usage.pct !== null ? hazardOf(…).color : COLORS.bridge`). The radar in `ui/pane.tsx:16` repeats the same rule with a different fallback.

**Cost:** UI rules and the colour palette leak into `events`, which then has to import `COLORS`, `hazardOf` and `PANE_MIN_WIDTH` from the UI barrel. That keeps the barrel wider than it needs to be (see R1-18).

**Fix:** Add `uiContext({ els, surface, bodyColumns, now, usage, view, actions })` in `src/ui/context.ts`. `render.tsx` passes only raw values.

### R1-12 · design · `src/forcefield/classify.ts:21-30,42-50`

**What:** `folderStep` and `classifySegment` read like queries, but `folderStep` pushes onto `scope.pushed` and `popd` pops it. Meanwhile `classifyAll` assigns `scope.dir` and `scope.subshells` itself.

**Cost:** The pushd stack changes in a function that returns a `Step`, so the scope's state is spread over three functions, which is hard to follow and to test.

**Fix:** Return the stack change in the step (`{ cd, push?: Dir, pop?: true }`) and apply every scope change in `classifyAll`'s loop. Alternatively, rename to `applyFolderStep`.

## Convention

### R1-13 · convention (one concern per file) · `src/ui/theme.ts:65-84`, `src/ui/hazard.ts:31-35`

### R1-14 · convention · `src/ui/modules/shields.tsx:66-78,95-101`, `src/ui/modules/mission.tsx:17-27`, `src/ui/modules/probes.tsx:16-19`, `src/forcefield/directives.ts:59-62`

**What:** These are multi-line arrow helpers declared inside functions: `deckButton`, `row`, `power`, `dot` and `isMatch`. The convention allows arrows for callbacks and one-liners only.

**Cost:** Hidden components with no names in the tree, and no way to test them alone.

### R1-15 · convention · `src/domain/fleet.ts:45-48`, `src/domain/shields.ts:34-38`

**What:** `statusOf(reason: string)` and `checkVerdict(decision: string, …)` map closed engine unions with `if` chains: `TurnCompleteReason` is `'answer' | 'aborted' | 'refusal' | 'error'`, and `ToolCheckDecision` is `'allow' | 'ask' | 'deny'`. The convention asks for a `Record<Key, …>` table.

**Cost:** A new engine reason or decision falls through silently ('failed' or 'ask') instead of failing to type-check.

**Fix:** `const SHUTTLE_STATUS_OF: Record<TurnCompleteReason, ShuttleStatus>` and `const VERDICT_OF: Record<ToolCheckDecision, Verdict>`, with both parameters typed by the engine unions.

### R1-16 · convention · `hooks/skywatch.ts:5`, `src/ui/clients/clock.tsx:11`, `src/ui/clients/loader.tsx:36`

**What:** `register`, `Clock` and `Loader` are exported arrow consts. The convention says exported functions are `function` declarations.

**Cost:** Small, but it is the one convention every reader checks first, and the exception is undocumented.

**Fix:** Either write `export function register(on: On, options: Readonly<Record<string, unknown>>): void`, or document in `conventions.md` that values typed by an engine function type (`Register`, `ClientModule`) are exempt.

### R1-17 · convention (review 01 C12, incomplete) · `src/forcefield/index.ts:7-8`, `tests/ui/beacon.test.ts:4`

### R1-18 · convention (unused exports) · `src/forcefield/measure/index.ts:11`, `src/forcefield/index.ts:3-4`, `src/core/config.ts:4,10`, `src/forcefield/directives.ts:6`

### R1-19 · convention (review 01 C10, incomplete) · `src/ui/modules/shuttle-card.tsx:13-16`, `src/ui/modules/blackbox.tsx:10-11`

**What:** These widths are still hand-counted:
- `STATUS_EXTRAS = 12` and `LOADER_EXTRAS = 6` in the card title
- `WRITER_WIDTH = 13` and `COST_WIDTH = 16` in the black box

`COST_WIDTH` assumes a cost text of 14 cells plus two spaces. `  ↑1.2M ↓45k $12.34` is 19.

**Cost:** For expensive jumps the text column is overestimated by 3 cells, so `Fold` lets a "two-line" entry wrap to three. A hand count also drifts silently whenever a glyph or gap changes.

**Fix:**

- Derive the card extras from their parts (glyph and space, `fmtTimer(0)` width, chevron).

### R1-32 · test · `tests/support/world.ts:24-31`

**What:** `fileText` matches a file by a path's suffix. A project-only `files: { '.claude/skywatch.directives': … }` therefore also answers `${HOME}/.claude/skywatch.directives`, so the forcefield tests load every directive twice, once as `~/…` and once as the project's.

**Fix:** Match absolute keys exactly, and resolve relative keys against `CWD` only (`path === name || path === \`${CWD}/${name}\``).
